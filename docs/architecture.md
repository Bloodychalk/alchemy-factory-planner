# 实现结构

`web/data.js` 是标准 JSON 验证、旧中文键名转换及上游数据常量的非执行式解析器；`web/planning.js` 是调用参考规则引擎的推荐与审计层。原引擎通过固定提交、SHA-256 校验后的文件在 Worker 中加载，不从配方 JSON 执行代码。

参考文件原始版本在本机缓存，修复/适配只作用于运行时副本：修正旧编辑器 switch 分支贯穿，为所有旧 localStorage 键加项目命名空间。计算内部使用规范英文键；参考画布中只替换显示名称，不改写数据标识。

`web/runtime.js` 将参考画布装入只有脚本权限、没有同源权限的 sandbox iframe。它使用传入的已解算速率，复用上游节点、连线、缩放和布局；采购、内部供给和净交付是明确的边界节点。图形摘要使用主结果，避免参考画布的浮点机器统计和整数建造数相互矛盾。只允许向父页面发送就绪通知及经检查的节点位置。

推荐保留 8 个最佳可行状态，至多 6 轮、默认 5 秒。每轮改变一条配方或有效修饰参数。现有炼金搜索纯函数提供两/三输入组合候选；高级炼金炉遍历催化剂组合，悖论配方可指定投入。候选数量和时间限制会影响推荐，不声称全局最优。

每次运行包括自供与回收，必要时迭代调整目标的毛产出以满足净交付。审计按实际工序的输入输出重新累加物料，验证缺口、燃料热值与营养消耗。缺少价格、隐式关闭自供、深度截断或非有限值均不能作为成功推荐。

`desktop/runtime.py` 在用户目录缓存经校验的参考资源；ZIP 一次下载，逐文件验证，绝不直接解压不受信任路径。`desktop/wiki.py` 从 Wiki 页面发现当前数据模块，提取 JSON 常量并更新对应配方，下载文件不会作为 Python/JavaScript 执行。`desktop/main.py` 通过 loopback 静态服务和 pywebview 本机桥提供文件操作；公开页面不能访问该桥。

打包产物只收集 Python 宿主和 `web/` 原创适配层。构建过程的测试缓存不在打包目录，也不上传到 Pages。公开工作流不会将研究快照、完整第三方数据库或图标复制到构建产物。
