# 设备级详细模式

界面提供简介、图形模式-总览、图形模式-详细。详细网络由总量结果派生，每个生产节点只代表一台设备，满载设备排在前面，最后一台按剩余工作量供料。接口限制可能增加设备数量，简介和总览同步更新生产/供热计数。每个端口只连接一个带段；需要分流或合流时显式插入一进二出、二进一出的物流构件。共享输出先接过滤分流，再分配到消费者。物料、热量和营养需求不会以“内部供给”边界结束。

燃料连接到逐台供热设备，再以热连接服务生产设备。当前使用保守的一炉一生产设备方案，只接受尺寸可容纳的组合，未优化共炉。采购入口包含采购传送门及外部资金银行端；成品与副产物仅显示出口。货币沿用参考模型每带位置 50 枚的占带规则。采购及银行设备的建造材料另计，持续采购费用不包含一次性设备费用。

## 规则来源和安全边界

`web/logistics-rules.json` 记录版本 1.1.5024 下各机器页面展示的输入输出口数量及来源链接（Alchemy Factory Recipes 的机器数据页）。这些数据已与页面核对，不代表实机逐项验证。自定义 JSON 可用 `logistics.machines` 覆盖规则；每个配置包括 `status: "verified"`、`beltIn`、`beltOut`、`pipeIn`、`pipeOut` 和来源信息。

传送带研究倍率、优先分流/合流的口数及优先顺序来自同版本的[物流指南](https://alchemyfactoryrecipes.com/guides/logistics)。优先端口在图中使用珊瑚色，对应线路标记“优先”。构件需要游戏五级解锁；当前计算器不筛选玩家解锁进度。采购、银行与生产/供热设备的已知建造材料会统计；未收录的物流构件建造材料不计入，带段也不等于实际格子长度。

**当前严格暂停的情况**：未收录接口的机器；多种输入必须混带、但配给控制结构尚未核实的配方；未指定容量规则的液体管道；虚拟组合物；蒸汽供热转换链。不会用假设的无限容量或比例分流器绘制这些路线。主界面保留总览，详细页列出缺失项。自定义资料已核实管道能力时，可提供正数 `logistics.pipeCapacity`（单位/分钟）；固体、管道及热连接分别计量。当前不支持用自定义数值绕过蒸汽转换链核实。

详细图是长期平均吞吐的设备接线图，不是游戏格子蓝图或逐帧仿真。启动库存仍见导出的方案报告。供料限流和缺料停机表示平均负载，不提供游戏不存在的调速功能。不进行机器、配方或传送带数量的全局最优证明。

详细规划细化当前选定的推荐路线，增加受物流限制的设备；暂不为了通过详细规则检查而另行搜索替代配方。

## 交互与存档

G6 5.1.1（MIT）绘制端口和线路，ELK 0.12.1（EPL-2.0）在独立 Worker 中布局。库文件和许可证位于 `web/vendor/`，按需载入，无 CDN 运行依赖。节点可以拖动，画布可以缩放和适配；点击节点查看端口明细。

方案保存为版本 2，同时接受版本 1。详细网络重新生成并审计；设备与网络指纹相同才复用保存的位置。两个图形模式分别保存布局。超出 10,000 节点或 30,000 线路时停止；生成和布局分别设 10 秒预算。未通过审计不发布详细网络。

## 验证

自动测试覆盖 60/72/90 木材每分钟的单台负载、超过一条带的并行交付、炉子与受热设备连接、缺规则阻断、篡改流量/端口归属/容量拒绝、共享产物过滤、肥料直连、管道容量缺失与显式容量、物流瓶颈增加设备、千台设备不聚合。完整旧计算回归保留。

2026-11-19：24 项 JavaScript 计算测试、4 项 Python 数据适配测试及静态资源检查通过。浏览器验收包含千台生产设备（2,510 设备/构件、3,500 带段）的独立绘制，版本 1/2 方案导入、版本 2 导出及重新导入、缩放/适配、节点端口明细、缺少管道规则时的错误与总览切换。未进行游戏内实机搭建测试。
